deploy-probe-v1
Diagnostic only. Exists to answer one question: does a NEWLY ADDED file under
public/ become reachable after a Workers Build?

Context: advisory-agreement.pdf, assets/sign-agreement.js and
assets/vendor/pdf-lib.min.js were all confirmed serving HTTP 200 earlier, then
began returning 404 while every file that predated them kept serving normally.
A clean isolated deploy did not fix it. Cloudflare's documented limits (25 MiB
per file, 20,000 files) are nowhere near being hit, there is no .assetsignore,
and worker.js's serveAsset is byte-for-byte unchanged.

If this file serves 200 while those three still 404, the problem is specific to
those paths. If this file 404s too, newly added static assets are not being
published at all, and the Workers Build asset-upload step is the culprit.

Safe to delete once the 404 is resolved.
